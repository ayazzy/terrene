# Terrene current state

> Repository implementation is authoritative where this document is stale.

This is an operational map of what exists on 14 September 2026. Inspect the relevant code, tests and linked implementation reports before changing it.

## Product architecture

- React 19 and TypeScript frontend built through the Vinext/Vite Sites scaffold, with MapLibre for geographic views.
- FastAPI API and a lease-based Python worker sharing SQLAlchemy models and deterministic processing code.
- PostgreSQL/PostGIS is the intended database; SQLite and Shapely provide the local/test path.
- Content-addressed object storage uses `data/objects` locally and requires private R2-compatible storage when hosted.
- Sites, boundary versions, assessments/jobs, dataset versions/features, reports, Evidence Snapshots and ModuleRuns are persisted. Existing tenant/auth controls are implemented, but the hosted external stack has not been deployed end to end.

See [Architecture](ARCHITECTURE.md), [Nature Intelligence](NATURE-INTELLIGENCE.md) and [data/source rules](DATA.md).

## Implemented capabilities

- Create sites from a drawn or uploaded Polygon/MultiPolygon in a contextual editor over the persistent operating map; validate, version and preserve boundary history.
- Submit deterministic assessments with pinned dataset/model configuration, deduplication, worker leases/retries/fencing and immutable saved results.
- Inspect portfolio sites in map-first or list mode; open the Site Analysis Workspace across Overview, Evidence, Models and History. Screening Context is the default Overview and the wetland assessment is a secondary Terrene Reasoning module.
- View source lineage and exact bounded overlay geometry, compare selected sites, record a current team review status, and export self-contained HTML reports.
- Project legacy saved assessments into immutable `land_evidence_v1` snapshots without changing the original assessment.
- Bind a committed snapshot through `wetland_input_binding_v1`, execute the unchanged wetland model, and persist an immutable ModuleRun.
- Intentionally prepare or reuse Screening Context v1 for a selected saved assessment, inspect its non-scoring facts/gaps/provenance in Overview, and download a self-contained HTML review artifact.
- Read the built-world objects attached to an immutable Evidence Snapshot through authenticated, organization-scoped `infrastructure_map_scene_v1`, without changing their authoritative EPSG:27700 evidence; the historical Screening Context map-feature contract remains available unchanged.
- View and select persisted buildings, functional sites, railway tracks and railway stations through native MapLibre GeoJSON layers and rendered-feature selection, with truthful per-layer availability, parcel/source inspection and evidence-gated building extrusion. The primary map now uses an operator-grade dark vector presentation, generated evidence legends, one mutually exclusive left-side surface and a responsive docked/bottom-sheet inspector.
- Create/read minimal organization-owned Project Subjects without requiring a Site, and submit/list/read immutable human-structured `project_evidence_v1` source-assertion bundles.
- Bind explicit Project Evidence bundles through `project_evidence_binding_v1`, run deterministic `project_intelligence_v1`, and list/read immutable project-specific runs.
- Inspect Project Subjects, exact source assertions, Terrene conclusions, conflicts, unresolved questions and historical runs in the shared read-only entity dossier beside the persistent map.
- Reproduce the Beacon Fen Sprint 003 validation baseline from a curated human-structured official consent excerpt without fabricating a Site, construction status or exact grid date; five semantically incompatible public assertions remain explicitly excluded from the v1 bundle.

## Terrene Earth today

`land_evidence_v1` registry v4 represents reusable observations, gaps, capabilities, definitions, source/raw references and lineage for immutable parcel boundaries. Registry v3 introduced these built-world objects:

- `MappedBuildingObject`
- `FunctionalSiteObject`
- `RailwayTrackObject`
- `RailwayStationObject`

`ParcelObjectRelationship` records explicit topology such as `contained_within`, `overlaps`, `touches`, `crosses`, `intersects` and `minimum_distance`, with source and processing provenance. Derived observations include mapped building and functional-site overlap, mapped railway length within a parcel, and minimum track/station distance when search coverage is complete.

Registry v4 adds `BuildingHeightObservation` without mutating `MappedBuildingObject`. Each height is the full-precision P90 of a boundary-buffered, median/MAD-filtered native 1 m `DSM − DTM` sample, linked to exact retained DSM/DTM artifacts. Missing or unsafe evidence is an object-linked gap and never a default extrusion. Registries v1–v3 remain supported byte-for-byte.

`project_evidence_v1` is a separate Terrene Earth contract for attributed project assertions. It retains exact source versions, excerpts and locators; publication, recording and effective/target dates; a bounded planning/construction/grid-target vocabulary; explicit correction lineage; and an optional pin to one committed land Evidence Snapshot. Contradictory claims coexist and no claim is promoted to a Terrene conclusion.

Priority Habitat Inventory observations preserve contributing source features and mapped habitat classes. Known mapped zero is represented separately from missing, partial, outside-coverage or failed evidence.

## Terrene Reasoning today

The historical wetland reasoning module is `wetland_restoration_v0_1`, using retained historical feature and processing identifiers such as `crc_wetland_features_v0_1_1`. It separates physical potential, current restoration need and implementation feasibility and refuses an overall result when required evidence is insufficient. Its snapshot execution path records the binding, model specification/signature, result and immutable ModuleRun identity.

The 12 retained Oxford verification locations have inspectable physical and hydrological components, but the model still reports overall `INSUFFICIENT_DATA`. New Priority Habitat and OpenMap Local evidence is intentionally not silently rebound into the historical wetland model.

`site_screening_context_v1` adds deterministic, offline human-review context over a committed snapshot through `screening_context_binding_v1`. It preserves source-bounded facts and gaps, qualifies mapped zeros, presents fixed source-semantic comparisons and asks unresolved review questions. It produces no score or progression decision. These are pilot rules, not customer-validated requirements.

`project_intelligence_v1` is deterministic reasoning over one explicit `project_evidence_binding_v1`. It reports bounded lifecycle stage, separate planning/construction findings, grid target states, conflicts and evidence-grounded questions. Explicit corrections supersede active use without erasing history; recency alone never resolves conflict, and elapsed targets do not establish outcomes. Results include exact claim/source-version/passage references and no score or recommendation.

## Application/UI state

The current home is a map-first portfolio view with a preserved list workflow. Its list is a Terrene site-intelligence ledger rather than a generic administration table: a compact portfolio command header, retained-site and evidence-layer signals, technical site identifiers, visual coverage tracks and clearly separated screening/team-review states support scanning and comparison without changing their semantics. The Site Analysis Workspace leads with a compact professional site brief: a deterministic presentation policy selects a high-level site picture, approximately six high-signal retained facts, consequential known gaps and existing human diligence questions without creating a score or unsupported narrative. Exact facts/gaps/provenance remain under Evidence, the unchanged wetland assessment is one module under Models, and immutable assessment selection remains under History. See [Site Analysis Workspace site brief](SITE-ANALYSIS-WORKSPACE-SITE-BRIEF.md).

Site identity, boundary, area, assessment state/date, team review status and secondary actions share one compact band. Wetland export is contained within its Models module. Unprepared Screening Context and no-assessment states retain useful site/boundary context and one explicit action; ordinary reads still create no immutable records.

The detailed Evidence view is a compact index: source-bounded domains, facts, gaps, review context and provenance are progressively disclosed instead of rendered as one continuous technical document. Models presents the single current wetland module summary-first, keeps analytical components and mapped reference layers collapsed until requested, and opens observation provenance in a closable drawer that preserves the originating list and section.

One shared site-workspace controller scopes the selected assessment, Screening Context lifecycle, history selection, map/evidence focus, exports and workspace controls. Switching sites or historical assessments clears stale artifact views and keys Screening Context to the exact assessment/site/boundary identity. Historical map, boundary, Earth evidence, context and model output move together. The desktop review panel is wider; at narrow widths the map and independently scrollable analytical workspace stack deliberately. The UI remains a small-portfolio application and fetches site/history collections without pagination.

One typed Infrastructure Operating Picture navigation contract now owns operating mode, exact Site or Project Subject selection, selected historical Site assessment or Project Intelligence run, dossier section/visibility and meaningful layer visibility. That state is deterministically URL-addressable and restores through reload and browser Back/Forward. Invalid, inconsistent or unavailable authorized identities fail closed; late Site-history or Project Intelligence responses remain scoped and cannot replace the current entity. Map camera state remains session-local. A shared compact Terrene shell, one persistent primary MapLibre scene and one docked entity-dossier pattern now span geographic overview, Site investigation, Project Intelligence and Site boundary editing. The obsolete portfolio map and isolated boundary-editor map lifecycles have both been removed. Global search and the intentionally disclosed map roster index both Sites and Project Subjects with evidence and location state; the Project dossier no longer repeats a second entity list. At desktop widths of at least 1280 px the dossier is capped at 40% of the available content width. Its identity header and history banner do not shrink, while one bounded body owns vertical scrolling. Header actions and selected-object details respond to the dossier's own inline size rather than the browser viewport, and primary content surfaces share one internal gutter. Project Subjects render spatially only through an explicit authorized Site relationship; Site-less subjects such as Beacon Fen remain visibly unlocated and selecting them does not manufacture a pin or move the map. The primary map exposes a local ready-event measurement for development certification without presenting it as product telemetry. See [Sprint 004 Task 1](SPRINT-004-TASK-1-OPERATING-PICTURE-STATE.md), [Task 2](SPRINT-004-TASK-2-OPERATING-SHELL.md), [Task 3](SPRINT-004-TASK-3-ENTITY-MAP.md), [Task 4](SPRINT-004-TASK-4-ENTITY-DOSSIERS.md) and [Task 5](SPRINT-004-TASK-5-OPERATING-PICTURE-CERTIFICATION.md).

The primary analytical map consumes the exact Evidence Snapshot's `infrastructure_map_scene_v1` projection and renders Sites, linked Project Subjects and built-world objects as native MapLibre GeoJSON sources and semantic layers. Selection uses rendered-feature queries and feature state rather than SVG hit testing. The scene defaults to top-down 2D. A Perspective control appears only when valid object-level height evidence exists; it moves the camera to 55 degrees and enables the evidence-gated building extrusion layer, while returning to 2D restores pitch zero. Buildings without valid height remain flat outlines and have a distinct generated legend state. Source-bounded layer states remain available, mapped zero, unavailable, partial or unsupported. Object selection is shared with Overview/Evidence, does not move the default parcel focus, and replaces the Site diligence body with one focused Asset intelligence view containing the plain parcel relationship, measurement, source/release, LIDAR-height state and limitation. Retained relationship measurements are presented as separately labelled values without changing their stored precision or predicate. The Site identity header remains visible; returning restores the prior Site section and in-session scroll position. Exact asset identity remains URL-addressable, and selecting another object replaces the focused asset directly. Opening the desktop dossier or Site editor re-fits the relevant boundary within the remaining visible map canvas; closing it restores the full available context. Locate object is intentional. Hiding its layer, changing run, site or historical assessment clears selection. Unsaved drawing vertices alone use a temporary SVG overlay on the persistent MapLibre scene and are cleared between drawing sessions.

Oxford Station now has a reproducible external QA provisioner and an explicit three-level analyst path: Portfolio locates authorized Sites and Project Subjects, Site diligence holds the exact boundary/evidence/snapshot context, and Asset intelligence inspects one building, functional site, track or station. Exact asset identity and the optional related-parcel highlight are URL-addressable alongside the selected historical assessment. “Show related objects” highlights only retained typed parcel relationships and draws no inferred network connections. The provisioner refuses repository-local or non-empty storage, reacquires official EA DSM/DTM bytes and validates the expected 5 buildings, 2 functional sites, 7 tracks, 1 station and 23 relationships before reporting success.

The application chrome and map surfaces use a near-black/dark green-grey operating palette. Site boundaries are cyan, selection is amber, buildings are slate, functional sites are teal, railway colours are driven only by retained classification and stations are high-contrast. Layers, legend and entity roster are mutually exclusive left-side surfaces; the entity inspector is docked on desktop and becomes a bottom sheet on narrow screens. The generated legend exposes layer availability, height-backed versus flat buildings, retained rail classes, keyboard-selectable objects and source/retrieval timestamps. Concise map hover labels never broaden source semantics.

`NEXT_PUBLIC_BASEMAP_STYLE_URL` is the production vector-style configuration. `NEXT_PUBLIC_BASEMAP_URL` remains a legacy raster fallback for existing environments. Local development uses OpenFreeMap Dark when neither variable is set; this public service has no SLA and is not an implicit production dependency. Production without either configuration loads the Terrene scene on a dark blank base and displays an explicit configuration warning rather than silently using the public development service. A configured style that fails at runtime also falls back to that evidence-only dark base without hiding Terrene geometry. The UI distinguishes loading, failed scene, unavailable scene, historical unsupported height, partial height evidence and building-level gaps; stale scene requests are cancelled and generation-fenced so a prior assessment cannot replace the current one.

Screening Context is an explicit assessment action: POST creates/reuses a snapshot and ModuleRun; GET only discovers or reads stored records. History selection scopes the action to the saved assessment and boundary. Unsupported legacy evidence fails without rewriting it. Export labels current team review status separately from the immutable context. See [Screening Context v1](SCREENING-CONTEXT-V1.md).

`GET /api/screening-context-runs/{run_id}/map-features` integrity-checks the selected run and committed Evidence Snapshot, then deterministically presents only its persisted Building, FunctionalSite, RailwayTrack and RailwayStation objects as EPSG:4326 GeoJSON. Layer metadata distinguishes available objects, qualified mapped zero, unavailable, partial and unsupported evidence. The response retains safe source, classification, fingerprint, relationship and measurement linkage while omitting raw storage locations and source payloads; it creates no persistence and never substitutes current objects into a historical run.

`GET /api/land-evidence-snapshots/{snapshot_id}/map-scene` is the snapshot-native primary-map read contract. It revalidates the immutable manifest and exact snapshot/site/boundary/content envelope, transforms presentation geometry to WGS84, exposes semantic layer and capability states, and attaches safe source, relationship and object-level height evidence. The GET is tenant-scoped, no-store and read-only. Registry v3 scenes remain selectable with height marked unsupported; registry v4 scenes expose observations or explicit gaps without default values.

The Screening Context read lifecycle is finite: stored, absent, unsupported, authentication/authorization and server/network outcomes are distinct; unresolved reads recover to Retry after 15 seconds. Routine workspace refreshes do not restart an unchanged assessment read, and cancelled or stale assessment responses cannot replace the selected assessment's context.

The read-only Project Intelligence content is docked beside the persistent map through the same entity-dossier shell as Sites. It lazily reads Project Subjects and immutable run history, allows explicit historical selection, visually separates source assertions from Terrene conclusions, and routes conclusion references to exact retained source passages. It provides no evidence/project editor or workflow action.

Versioned Design Studies remain API-only. The frontend has no Alternative editor, design map tools or Design Revision history UI.

## Known limitations

- The wetland model is unvalidated and cannot yet rank the retained real locations defensibly.
- Hosted Supabase/Render/R2 credentials and end-to-end tenant acceptance have not been configured or verified; the reserved Sites frontend is not a deployed product.
- Team review status is not yet an immutable historical Decision record.

- Proposed design revisions accept bounded Polygon/MultiPolygon GeoJSON only; there is no CAD/PDF ingestion, centreline buffering, layout generation, environmental intersection, impact calculation or A/B consequence comparison.

- The operating picture is an evidence-complete engineering prototype, not yet a customer-validated analyst workflow.
